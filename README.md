# Doom for the EK-RA8P1

A port of Doom (shareware episode, `doom1.wad`) to the Renesas EK-RA8P1
(R7KA8P1KF, Cortex-M85 @ 1 GHz), built on FSP 6.5 + FreeRTOS with the Arm
LLVM toolchain (ATfE 22.1). The engine is [doomgeneric](https://github.com/ozkl/doomgeneric)
(GPL-2.0, derived from Chocolate Doom); everything board-specific is in `src/port`.

| Item       | Implementation |
|------------|----------------|
| Display    | 7" 1024x600 parallel RGB panel (RTKLCDPAR1S00001BE) on the Parallel Graphics Expansion Port. GLCDC layer in **CLUT8** mode, so Doom's palette is loaded into the hardware colour table. 320x200 is scaled to 800x600 (4:3) and double-buffered in SDRAM, with page flips on vsync. About 56 fps (panel refresh). |
| Controller | Sony DualSense (PS5) or DualShock 4 (PS4) on the **USB high-speed port**, using FSP USB Host HID (`r_usb_hhid`). The light bar turns red once the controller is recognised. |
| WAD        | Stored in the external octal flash at `0x90000000` and copied to SDRAM at boot (~1 s). |
| Memory     | Doom zone 24 MB, WAD copy and RAM file system all in SDRAM; D-cache enabled. |
| Console    | `printf` output goes to SEGGER RTT channel 0 (use J-Link RTT Viewer). |

## Getting started

1. **Hardware:** fit the parallel display board on J1 (SW4-6 must be OFF, per the
   EK-RA8P1 user manual), plug the controller into the USB high-speed connector
   with a USB cable, and connect the debug USB port (J10) to the PC.
2. **Program the WAD (one time):** run the VS Code task **"Flash Doom WAD to OSPI"**,
   or `scripts\flash_wad.bat [path\to\iwad]`. This takes about a minute. To use a
   different IWAD (`doom.wad`, `doom2.wad`, up to 16 MB), pass its path; the game type
   is detected from the WAD's contents.
3. **Build and run:** build as described below, then download and run with the
   "Renesas GDB Debugging" configuration. A normal download only rewrites the
   internal MRAM, not the WAD.

If the screen shows **"NO IWAD IN OSPI FLASH"** (and the red LED blinks), step 2 hasn't been done.

## Controls

| Button            | In game                         | In menus |
|-------------------|---------------------------------|----------|
| Left stick        | Move / strafe (analog)          | Navigate |
| Right stick       | Turn (analog)                   | -        |
| D-pad             | Move / turn                     | Navigate |
| R2 or Square      | Fire                            | Select   |
| Cross             | Use (doors, switches)           | Select / "Yes" |
| Circle            | -                               | Back / "No" |
| L2 (hold)         | Toggle run (inverts always-run) | -        |
| L3 (click)        | Always-run on/off (default on)  | -        |
| R1 / L1           | Next / previous weapon          | -        |
| Triangle, touchpad| Automap                         | -        |
| Options, PS       | Menu                            | Close menu |
| Create            | Pause                           | -        |

Choosing an empty save slot with Cross names it automatically (e.g. `E1M3 SLOT1`).
Choosing *Quit Game* from the menu restarts the board.

## Port structure

```
doom/engine/            doomgeneric engine sources (third party, built with warnings suppressed)
doom/tools/patch_engine.py  small RA8_DOOM-guarded engine patches (already applied, idempotent)
doom/wad/doom1.wad      shareware IWAD v1.9 (MD5 f0cefca49926d00903cf57551d901abe)
scripts/flash_wad.bat   programs the IWAD into OSPI flash with J-Link
scripts/ra8p1_ospi_reset.JLinkScript  resets the octal flash before J-Link programs it
src/new_thread0_entry.c boot sequence and main game loop
src/port/i_video_ra8.c  GLCDC CLUT8 video, palette, scaling, boot/error screen
src/port/i_input_ra8.c  game pad -> Doom key events, menu repeat, analog axes
src/port/usb_gamepad.c  USB host task, DualSense / DS4 report parsing, light bar
src/port/wad_loader.c   OSPI (1S-1S-1S memory mapped) -> SDRAM IWAD copy
src/port/ramfs.c        RAM file system behind fopen() (WAD, default.cfg, save games)
src/port/doom_platform.c  DG_* hooks, SDRAM arena, memory-mapped WAD class, quit/exit
src/port/rtt_log.c      SEGGER RTT console (stdout/stderr)
```

FSP configuration changes (in `configuration.xml`): SDRAM and D-cache enabled; heap 512 KB;
GLCDC (CLUT8 1024x600, panel timings for the 7" display, pixel clock 48 MHz);
OSPI_B unit 0 / CS1 with 4-byte addressing and OCTACLK /4; USB Host HID on USB_IP1 (USBHS)
in full-speed mode (the FSP HHID class does not support Hi-Speed); FreeRTOS dynamic allocation
with Heap 4 (64 KB), and a 64 KB stack for the game thread.

Known limitations:
- **No sound.**
- **Save games and settings live in RAM** and are lost on reset or power off.

# Renesas RA CMake Project

This project is generated by RASC.

###  Building via CLI:
Configure: ```cmake -DARM_TOOLCHAIN_PATH="/your/toolchain/path" -DCMAKE_TOOLCHAIN_FILE=cmake/gcc.cmake  -G Ninja -B build/Debug```

- Ex.: ```cmake -DARM_TOOLCHAIN_PATH="C:/LLVMEmbeddedToolchainForArm-17.0.1-Windows-x86_64/bin" -DCMAKE_TOOLCHAIN_FILE=cmake/llvm.cmake  -G Ninja -B build/Debug```
- Ex.: ```cmake -DARM_TOOLCHAIN_PATH="C:/LLVMEmbeddedToolchainForArm-17.0.1-Windows-x86_64/bin" -DCMAKE_TOOLCHAIN_FILE=cmake/llvm.cmake  -DCMAKE_BUILD_TYPE=Release -G Ninja -B build/Release```

Build: ```cmake --build build/Debug```


### Configure via Visual Studio Code
- Set ARM_LLVM_TOOLCHAIN_PATH as an environment variable before starting VS code or alternatively set ARM_TOOLCHAIN_PATH in .vscode/cmake-kits.json
- Select "ARM LLVM kit with toolchainFile" kit in VS Code status bar
- It is recommended to avoid spaces in the toolchain and project paths as they might be interpreted as delimiters by CMake and the other build tools.

Example:

```set ARM_LLVM_TOOLCHAIN_PATH=C:/LLVMEmbeddedToolchainForArm-17.0.1-Windows-x86_64/bin```
```cd "c:/data/Work/workspaces_vscode/ra8p1_doom/" && code .```

- Click build in VS Code status bar
